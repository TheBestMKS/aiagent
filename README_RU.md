# AI Agent

> Версия 1.58.1: сборщик заранее проверяет свободное место, безопасно очищает только генерируемые кеши и сохраняет уже готовые артефакты при частичном сбое.

AI Agent — кроссплатформенное Flutter-приложение для работы с локальными и OpenAI-совместимыми моделями, проектами, файлами, консолью, документами и локальными инструментами.

## Версия

Текущая версия: `1.58.1+64`.

Единственным источником версии является строка `version:` в `pubspec.yaml`. Сборщик автоматически использует часть до `+` в имени релиза и числовую часть после `+` как Android build number.

## Требования к сборке на Windows

Flutter должен находиться по адресу:

```text
N:\Codex\Compilers\flutter\bin\flutter.bat
```

Проект предполагается размещать в:

```text
N:\Codex\AIAgent
```

Для Windows-сборки также требуются Visual Studio Build Tools с компонентами C++ Desktop. Для Android необходимы Android SDK/JDK, настроенные для используемого Flutter SDK.

## Сборочные скрипты

Основной скрипт:

```powershell
.\build.ps1 -Target All
```

Удобные BAT-обёртки:

```text
build_all.bat       — проверка, тесты и сборка Windows + Web + Android
build_windows.bat   — сборка Windows
build_web.bat       — сборка Web
build_android.bat   — сборка Android APK
analyze.bat         — анализ исходников
run_tests.bat       — тесты
diagnose_build_env.bat — диагностика Flutter и окружения
```

Для пропуска анализа и тестов можно перед запуском задать `SKIP_CHECKS=1` либо передать PowerShell-параметр `-SkipChecks`.

Сборщик поддерживает возобновление релиза: при повторном запуске той же версии уже созданные артефакты пропускаются. Для полной пересборки используйте `build_all.bat -ForceRebuild`. Перед каждой платформой проверяется свободное место; при недостатке места удаляются только генерируемые кеши. Порог Android можно изменить параметром `-MinimumAndroidFreeSpaceGB`, а автоматическую очистку отключить через `-DisableLowDiskCleanup`.

## Результат

Для версии `1.58.1+64` полный запуск `build_all.bat` создаёт:

```text
N:\Codex\AIAgent\dist\AIAgent_v.1.58.1\
  AIAgent_v.1.58.1_win.zip
  AIAgent_v.1.58.1_web.zip
  AIAgent_v.1.58.1_android.apk
```

Windows ZIP содержит `AIAgent.exe` и все необходимые библиотеки. Web ZIP содержит готовое содержимое `build\web`, которое нужно распаковать в корень веб-сервера. APK формируется в release-режиме.

## Как работает сборщик

Скрипт проверяет фиксированный путь к Flutter, читает версию из `pubspec.yaml`, включает Windows/Web, создаёт отсутствующие платформенные runner-файлы, исправляет имена приложения и Android-разрешения, выполняет `flutter pub get`, анализ и тесты, собирает три платформы и упаковывает результаты с единообразными именами. Перед каждой платформой он проверяет свободное место. При заполнении диска уже созданные ZIP/APK остаются в `dist`, а безопасная очистка затрагивает только `build`, `.dart_tool/flutter_build` и локальные кеши Gradle/CMake.

Web-версия использует отдельную безопасную точку входа. Полный доступ к файловой системе, процессам, консоли и локальному `llama.cpp` остаётся в Windows-приложении; браузерная версия не пытается компилировать модули на основе `dart:io`.

## Поведение при ошибке сборки

После неудачной команды агент сначала определяет, относится ли ошибка к исходнику, линковке, CMake, параметрам инструмента, зависимости, окружению или отсутствующему артефакту. `main.cpp` и другие исходники нельзя менять, если компилятор не указал конкретный файл и строку. Агент обязан прочитать диапазон вокруг указанной строки. Предложенная инструментом команда `--help` выполняется автоматически. После одной подтверждённой правки следующим действием обязательно становится повтор исходной сборки. Подробности: `docs/BUILD_DIAGNOSTICS_V1_56_RU.md`.

## Структура исходников

- `lib/main.dart` — минимальная точка запуска.
- `lib/app/app_entry.dart` — выбор обычной или Web-реализации через условный импорт.
- `lib/app/ai_agent_app.dart` — полный Windows/Android-интерфейс.
- `lib/app/ai_agent_web_app.dart` — Web-безопасный адаптивный интерфейс.
- `lib/controllers/agent_controller.dart` — координация агента и проектов.
- `lib/agent_core/build/` — классификация ошибок сборки и безопасное формирование команд C++.
- `lib/agent_core/runs/` — устойчивые контрольные точки и история запусков.
- `lib/agent_core/safety/` — защита от циклических и повторно ошибочных действий.
- `lib/agent_core/verification/` — реестр доказательств выполнения и оценка уверенности.
- `lib/widgets/` — отдельные виджеты восстановления, статуса и истории задач.
- `lib/tabs/` — вкладки чата, файлов, консоли и Web.
- `lib/document_tools/` — чтение, формирование и редактирование офисных документов.
- `tools/` — локальные компиляторы, утилиты и варианты `llama.cpp`.


## Локальное ядро памяти и поиска

В версии 1.54 добавлена встроенная память без облачной БД: записи имеют тип, область, источник, происхождение, уверенность, отметку проверки, версии и историю противоречий. Гибридный поиск объединяет точное совпадение, BM25-подобное ранжирование и символьное сходство, поэтому работает локально и поддерживает русские запросы.

Проверенный повторяемый способ переводится в `golden path` только при наличии фактической успешной проверки и хотя бы одного явно исключённого нерабочего подхода. Значения, похожие на API-ключи, токены и пароли, удаляются перед записью.

## Надёжность и восстановление задач

В версии 1.55 агент получил устойчивый журнал выполнения. Для каждой задачи в `.cppagent/runs` сохраняются исходный запрос, план, номер итерации, счётчики действий, последний инструмент, сокращённый результат и доказательства проверки. При аварийном закрытии или перезапуске проекта в чате появляется предложение продолжить задачу с предыдущего состояния либо закрыть её без продолжения. Продолжение сохраняет прежний ID запуска, начинает со следующей итерации и восстанавливает доказательства, последний exit code и защиту от циклов.

Реестр доказательств различает изменения файлов, команды, тесты, чтение, исследование и ошибки. Агент не считает программную задачу проверенной только по текстовому ответу или любой успешной команде: `run_command` засчитывается как проверка только для распознанной сборки, теста, анализатора или компилятора.

Секреты удаляются перед сохранением checkpoint, истории сеанса и журналов. Поддерживается рекурсивная маскировка вложенных аргументов, токенов, URL-учётных данных и приватных ключей.

Защита от циклов блокирует одинаковый вызов инструмента после нескольких повторов, повторение одной и той же ошибки и длительное чередование разных инструментов без измеримого прогресса. Инструмент `get_task_status` возвращает модели текущий план, доказательства, шлюз завершения и состояние защитного механизма, чтобы она могла сменить стратегию.

Централизованный шлюз завершения перечисляет недостающие изменения, тесты, исследования или исправления ошибок и не позволяет разрозненным эвристикам противоречить друг другу.

В настройках доступны:

- включение или отключение контрольных точек;
- защита от циклических вызовов;
- автоматическое сохранение только проверенных успешных решений;
- просмотр текущего плана и доказательств;
- история завершённых, отменённых и ошибочных запусков с возможностью очистки.

Подробности: `docs/AGENT_RELIABILITY_V1_55_RU.md`.

## Менеджер плагинов

В настройках доступен менеджер 11 плагинов-адаптеров. Плагины хранятся в отдельной папке `plugins`, могут включаться независимо, синхронизировать исходники с GitHub и проверять обновления по SHA ветки. Загрузка выполняется во временную папку; ZIP проверяется на выход за пределы каталога, после чего версия активируется атомарно с резервной копией.

Настройки позволяют:

- проверять обновления при запуске;
- показывать список обновлений с флажками выбора;
- включить фоновое автоматическое обновление без запроса;
- наблюдать ход операции в компактной строке состояния;
- отключать сетевые и чувствительные плагины;
- искать по локально синхронизированной документации без подключения к интернету.

Сетевые функции OpenSERP, каталогов API/провайдеров и OSINT не встроены в ядро. Они выполняются только через отдельные плагины и существующую систему разрешений агента. T3MP3ST представлен исключительно безопасным справочным адаптером: наступательные функции в программу не добавлены.

Подробности: `docs/PLUGIN_SYSTEM_RU.md` и `docs/SOURCE_REVIEW_RU.md`.

## Надёжная диагностика сборки

Версия 1.57.0 разделяет ошибки исходного кода, CMake-конфигурации, зависимостей, окружения и отсутствующих артефактов. Агент изменяет исходный файл только после сообщения компилятора с конкретным файлом и строкой. Для отсутствующего локального заголовка исправляется include-path в `CMakeLists.txt`; конфигурация CMake не считается успешной компиляцией, а после правки обязательна повторная сборка. Доверенная память создаётся только по фактической успешной проверке после последней ошибки.

Версия 1.57.1 восстанавливает обязательный пакет исходников `lib/agent_core/build`, случайно исключённый из предыдущего архива. Контроллер диагностики сборки, CMake-резолвер, построитель прямой команды C++ и тесты теперь поставляются вместе.
