# Исправление логики диагностики сборки — AIAgent 1.57.0

## Ошибки, выявленные по журналу

1. `cmake --build .` выполнялся до создания `CMakeCache.txt`, но ошибка не распознавалась как ошибка конфигурации.
2. Успешный запуск `cmake -S . -B build` ошибочно мог считаться полноценной проверкой программы.
3. Ошибка `fatal error: ImageClassifier.h: No such file or directory` связывалась с `ImageClassifier.cpp`, хотя заголовок уже находился в `include/` и требовалось исправить include-path CMake.
4. Модель могла передать произвольный текст `verification` в `remember_solution` и создать ложный доверенный golden path.
5. Заблокированные повторные команды чередовались с `get_task_status`, не увеличивая счётчик отсутствия прогресса.

## Новая последовательность

- Ошибка сначала классифицируется: source, linker, CMake configuration, dependency, environment, tool usage или artifact.
- Для отсутствующего CMake cache команда нормализуется в конфигурацию `build` и сборку этого каталога.
- Конфигурация CMake сама по себе не закрывает задачу и не создаёт passing verification.
- Если отсутствующий заголовок найден внутри проекта, исходники запрещено менять; существующая цель CMake сохраняется, к ней добавляется `target_include_directories`.
- После исправления немедленно повторяется сборка.
- Доверенная процедура создаётся только по evidence ledger: после последней ошибки должна существовать реальная успешная build/test/analyze-команда.
- Три последовательных заблокированных действия останавливают запуск.
