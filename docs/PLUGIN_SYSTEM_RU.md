# Плагинная система и локальное усовершенствование агента — v1.54

## Цель

Архитектура разделяет функции на две группы:

1. **Локальное ядро** — алгоритмы, которые работают без обращения к внешним данным: память, поиск, планирование, проверка, сжатие контекста и контроль разрешений.
2. **Плагины** — функции, чьи данные меняются в интернете либо чьё выполнение обращается к внешним сайтам, API, моделям или сетевым сервисам.

Такое разделение сохраняет офлайн-режим и не даёт сетевым возможностям незаметно стать частью доверенного ядра.

## Что перенесено в локальное ядро

### Гибридный поиск

`lib/agent_core/retrieval/hybrid_retrieval.dart` объединяет:

- точное совпадение фразы и заголовка;
- BM25-подобное ранжирование;
- совпадение терминов;
- символьное сходство триграмм;
- нормализацию русского и английского текста.

Поиск применяется к памяти и локально синхронизированной документации плагинов. Большие справочные файлы режутся по абзацам и Markdown-заголовкам на перекрывающиеся фрагменты, а подготовленный индекс кэшируется до смены commit SHA. Векторная БД, embeddings и сетевой API не требуются.

### Типизированная память

`lib/agent_core/memory/local_memory_service.dart` хранит append-only JSONL-журнал. Для каждой записи сохраняются:

- тип: инструкция, факт, решение, цель, обязательство, предпочтение, контекст, событие, обучение, наблюдение, артефакт или процедура;
- глобальная либо проектная область;
- источник и происхождение;
- уверенность;
- признак и способ проверки;
- известные нерабочие подходы;
- версия, заменяемая запись и история противоречий;
- теги и временные метки.

При поиске учитываются не только текстовые совпадения, но и уверенность, успешная проверка, точное совпадение проекта и временная актуальность. Для целей, обязательств, событий и предпочтений свежесть имеет больший вес.

Секреты, похожие на токены, API-ключи и пароли, маскируются до записи.

### Самообучение без закрепления догадок

Процедура получает статус `golden path` только при выполнении двух условий:

1. есть фактическая успешная проверка;
2. сохранён хотя бы один конкретный исключённый нерабочий подход.

Непроверенное решение остаётся обычной предварительной записью памяти.

### Управление контекстом

`ToolOutputCompactor` не удаляет полный результат. Исходный вывод остаётся в журналах, а в контекст модели передаются важные строки, начало и конец. Это уменьшает переполнение контекста без сокрытия диагностической информации от пользователя.

### Безопасный harness

В ядре используются безопасные общие принципы:

- явные разрешения на инструменты;
- сетевые действия блокируются при отключённом интернете;
- чувствительные плагины требуют критического подтверждения;
- проверка результата отделена от заявления об успехе;
- длительные операции имеют состояние и прогресс;
- установленные источники заменяются только после проверки новой версии.

## Модульная структура менеджера

- `plugin_manager.dart` — каталог, состояния, включение и координация операций;
- `plugin_github_updater.dart` — GitHub API, загрузка, безопасная распаковка, staging и rollback;
- `plugin_reference_index.dart` — chunking, кэш и локальный поиск по документации.

## Обновление через GitHub

Состояние хранится в `plugins/plugin_state.json`. Для проверки используется текущий SHA настроенной ветки GitHub. Установка выполняется так:

1. архив коммита загружается в `plugins/.staging`;
2. ZIP декодируется с проверкой целостности;
3. абсолютные пути и сегменты `..` отклоняются;
4. действуют ограничения на размер загрузки, число ZIP-записей и суммарный распакованный объём;
5. проверяется наличие содержимого и README;
6. существующая версия перемещается в `plugins/.backup`;
7. новая версия атомарно активируется как `plugins/<id>/source`;
8. создаётся локальный `plugin.json` с репозиторием, SHA и разрешениями;
9. при ошибке восстанавливается резервная копия.

## Настройки обновления

- **Проверять при запуске** — проверяются синхронизированные плагины.
- **Автоматически без запроса** — найденные версии обновляются в фоне; проверка ZIP и распаковка вынесены из UI-isolate.
- При выключенном автообновлении показывается окно со списком и флажками.
- Компактная строка состояния показывает проверку, загрузку, количество ожидающих обновлений и ошибки.

## Ограничения и принцип доверия

Синхронизация исходников не означает автоматического доверия к ним. Включение плагина и разрешение его tool-вызова — отдельные действия. Справочные плагины читаются локально. Сетевые/командные плагины проходят через права проекта и критическое подтверждение. Синхронизация справочных исходников поддерживается в Windows, Linux и Android; Web-оболочка не загружает нативный менеджер из-за браузерной песочницы.
