# Архитектура агента 1.60

## Источники и границы заимствования

Реализация опирается на проверяемые механизмы из официальных источников:

- OpenAI Codex: <https://github.com/openai/codex>
- OpenCode: <https://github.com/anomalyco/opencode>
- OpenCode Agents: <https://opencode.ai/docs/agents>
- OpenCode Compaction: <https://opencode.ai/docs/compaction>
- Claude Code Memory: <https://code.claude.com/docs/en/memory>
- Claude Code Subagents: <https://code.claude.com/docs/en/sub-agents>
- Microsoft WSL commands: <https://learn.microsoft.com/windows/wsl/basic-commands>

Codex и OpenCode публикуют исходный код с открытыми лицензиями. Репозиторий Claude Code не содержит исходного кода ядра CLI, поэтому из Claude Code перенесены только публично документированные идеи памяти, изоляции контекста и передачи результата. Закрытый код не копировался.

## Жизненный цикл задачи

1. Контроллер читает режим проекта из `.cppagent/project_settings.json`.
2. В автоматическом режиме `TaskIntentAnalyzer` определяет основной и дополнительные домены. Явный режим задаёт основной домен, но не удаляет дополнительные требования пользователя.
3. `TaskGoalPlanner` фиксирует исходный запрос, предполагаемый наблюдаемый результат и начальные шаги исследования, выполнения, проверки и передачи результата.
4. Модель уточняет цель через `define_task_goal` и при необходимости рекурсивно добавляет шаги через `add_task_subtask`.
5. После каждого инструмента контроллер записывает фактический результат, exit code, изменения файлов, терминальную сессию и релевантные пути. Модель может уточнить состояние через `update_task_subtask` и `record_task_context`.
6. Завершение проходит через общий шлюз доказательств и проверку незавершённых узлов. Для программной задачи дополнительно требуется стандартный релиз.
7. Итоговое состояние и результирующие файлы сохраняются до вывода сообщения пользователю.

## Устойчивая память и сжатие

Для каждого запуска создаются:

```text
.cppagent/tasks/<task_id>/
  state.json
  handoff.md
```

`state.json` содержит структурированное дерево. `handoff.md` является каноническим текстовым представлением исходной цели, ожидаемого результата, подзадач, результатов, доказательств, артефактов и важных фактов. Значения ограничиваются при записи, секреты маскируются, а сам файл повторно добавляется в system-контекст дословно. Поэтому обычное сокращение истории диалога не меняет цель и не стирает удачные команды.

Проверенные команды компиляции и тестирования дублируются в глобальной типизированной памяти. Непроверенная догадка не получает статус успешной процедуры.

## Выход из циклов

Повтор одинакового вызова без нового состояния блокируется. После нескольких последовательных блокировок или разных безуспешных подходов запуск получает статус `awaitingUser`, сохраняет активный checkpoint и задаёт один вопрос о конкретном препятствии. Ответ пользователя добавляется как `USER_GUIDANCE` к тому же запуску. Статус не смешивается с явной кнопкой Stop.

## Терминал, WSL и удалённые системы

`InteractiveTerminalService` хранит постоянные PTY-сессии и транскрипт проекта. `wsl_list` вызывает `wsl.exe --list --verbose`. `terminal_open` с `backend=wsl` выбирает дистрибутив, рабочую папку и Linux-оболочку; путь `N:\Projects\Demo` преобразуется в `/mnt/n/Projects/Demo`. SSH, telnet, REPL и другие интерактивные программы продолжают работать в той же видимой пользователю вкладке.

## Стандарт релиза проекта

`package_project_release` разрешён только после зафиксированной успешной проверки. Он атомарно создаёт:

```text
release/<program>_<version>/
  SHA256SUMS.txt
  CHANGE_en.md
  CHANGE_ru.md
  README_en.md
  README_ru.md
  source_<version>.zip
  <program>_<version>_<platform>_<architecture>.<ext>
```

Из архива исходников исключаются `.git`, `.cppagent`, `release`, сборочные кеши и зависимости. Описания с TODO/placeholder отклоняются. Для каждого итогового файла вычисляется SHA-256, после чего структура повторно проверяется.

## Редактируемые промты

Настройки содержат отдельный редактор промтов общей логики, классификации, цели, декомпозиции, выполнения, проверки, восстановления, handoff, релиза, шести режимов и вопроса при блокировке. Пользователь видит описание каждого блока, может восстановить заводское значение и проверить собранный контекст на примере задачи до сохранения.
