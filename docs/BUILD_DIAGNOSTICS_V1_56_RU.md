# Диагностика сборки в AIAgent 1.56

## Назначение

Агент больше не должен менять прикладной исходный код после любой ошибки сборки. Сначала результат команды классифицируется детерминированным анализатором, а доступные действия ограничиваются типом подтверждённой ошибки.

## Классы ошибок

- `sourceCompile` — компилятор указал конкретный исходный файл и строку. Агент обязан сначала прочитать диапазон вокруг этой строки, затем внести одну минимальную правку и повторить ту же команду.
- `linker` — ошибка линковки. Сначала проверяются объектные файлы, библиотеки, `target_link_libraries` и сигнатуры символов.
- `buildConfiguration` — ошибка `CMakeLists.txt`, рабочей папки, путей `-S/-B`, цели или структуры проекта. Исходники блокируются.
- `toolUsage` — неверный параметр или синтаксис команды. Если программа предлагает `--help`, справка запускается до любых изменений.
- `dependency` — отсутствует заголовок, пакет или библиотека. Агент исправляет зависимости и пути, а не переписывает алгоритм.
- `environment` — не найден компилятор, генератор, команда, права или PATH. Проверяются локальные `tools` и окружение.
- `artifact` — процесс завершился, но ожидаемый файл не создан. Проверяются реальная команда, код процесса и путь артефакта.
- `unknown` — исходный код блокируется до получения дополнительной диагностики.

## Обязательная последовательность

1. Выполнить сборку и сохранить полный stdout/stderr и оба кода: эффективный `EXIT_CODE` и фактический `PROCESS_EXIT_CODE`.
2. Классифицировать ошибку.
3. Выполнить безопасную диагностическую команду, если она предложена инструментом. Автоматическая правка конфигурации разрешена только после успешной справки.
4. Исправить только подтверждённую причину.
5. После одной правки запретить любые другие инструменты: следующим действием должна быть повторная сборка.
6. Сначала повторить исходную команду сборки. Другую стратегию разрешается выбирать только после нового результата.
7. Считать задачу выполненной только после успешной проверки и существования ожидаемого артефакта.

## Защита от ошибочных действий

- `PROCESS_EXIT_CODE: 0` больше не перекрывает эффективный `EXIT_CODE: 2`, выставленный при отсутствии артефакта.
- `get_task_status` разрешён только один раз подряд и не увеличивает показатель прогресса.
- Запись, дополнение, замена, удаление, копирование и перемещение исходников проходят через единый шлюз разрешений после ошибки сборки.
- Для существующего исходника требуется `read_file` с диапазоном, включающим строку ошибки; усечённое чтение большого файла целиком не считается достаточным.
- Состояние диагностики сохраняется в checkpoint и восстанавливается после перезапуска программы.
- Автоматическое создание `CMakeLists.txt` выполняется только для явно подтверждённой ошибки отсутствующего `CMakeLists.txt`; другие ошибки генератора и параметров не маскируются перезаписью конфигурации.
- Windows-команда прямой компиляции изолирует каждое условие `if` скобками, чтобы `cmd.exe` не пропустил запуск компилятора.
