# Пошаговое выполнение и память AI Agent 1.61

## Задача реализации

Небольшой модели трудно одновременно удерживать большую цель, десятки схем
инструментов, структуру проекта и длинный вывод компилятора. Версия 1.61 не
пытается исправить это ещё одним длинным промтом. Управляющая программа сама
сохраняет состояние и выдаёт модели только ближайшее проверяемое действие.

## Цикл слабой модели

`GuidedExecutionCoach` выбирает одну из стадий:

1. `inspect` — определить структуру и штатный способ сборки;
2. `retrieve` — найти проверенную подсказку в контекстах и памяти;
3. `implement` — записать полный ближайший набор исходников;
4. `diagnose` — прочитать фактическую ошибку и затронутый файл;
5. `verify` — выполнить определённую проверку и реальную сборку;
6. `package` — упаковать только проверенные артефакты;
7. `deliver` — сверить критерии и сообщить результат.

Для небольшой или неизвестной локальной модели OpenAI tool schemas фильтруются
по стадии. Цель задачи, дерево подзадач, журнал доказательств и результаты
команд остаются в контроллере и не зависят от способности модели запомнить их.

`ProjectBuildRecipeDetector` распознаёт manifest/build-файлы и выдаёт
детерминированные команды. После изменения исходников рецепт сбрасывается и
строится заново. Ошибка компиляции разрешает точечное редактирование только
после чтения указанного компилятором файла; повторные одинаковые неудачи
переводят следующий шаг в поиск прошлых решений.

## Полный архив контекста

`ContextArchiveService` индексирует:

- `.cppagent/sessions` — диалоги и результаты инструментов;
- `.cppagent/tasks` — неизменяемую цель, подзадачи, контекст и артефакты;
- `.cppagent/runs` — контрольные точки и итог выполнения;
- `.cppagent/terminal` — команды и вывод постоянных консольных сессий;
- типизированную общую память;
- пользовательскую папку `documents`.

Файлы делятся на перекрывающиеся фрагменты. Неизменённые источники повторно не
извлекаются. Поиск выполняется локально, поддерживает области текущего проекта,
других проектов, всех проектов, общей памяти и литературы. Каждый результат
содержит стабильный `SOURCE_ID`; `context_read` дочитывает полный источник
частями. Перед записью в индекс маскируются секреты.

## Использованные инженерные принципы

- [Anthropic: Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) — ограниченный высокосигнальный контекст, получение сведений по требованию, внешние заметки и сохранение важных данных при сжатии.
- [OpenAI: A practical guide to building agents](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf) — ясные инструкции, ограниченный набор инструментов, проверяемые выходы и защитные механизмы вокруг модели.
- [OpenAI Codex compaction implementation](https://github.com/openai/codex/blob/main/codex-rs/core/src/compact.rs) — отдельное каноническое состояние, которое переносится через сжатие истории.
- [OpenCode tools documentation](https://opencode.ai/docs/tools/) — явные контракты инструментов и контролируемые разрешения на действия.

Эти идеи реализованы собственным кодом проекта; исходный код сторонних агентов
не копируется.
